## Repair 1 — Finding 4's DSP claims (proposal.md)

Verified against source, both claims hold.

- **Allpass unity-gain at DC.** `SchroederAllpassSection::Process` (`app/dsp/StereoField.hpp:99-108`) implements `y[n] = -a*x[n] + x[n-M] + a*y[n-M]`. Its transfer function is `H(z) = (z^-M - a)/(1 - a*z^-M)`; at `z=1` this is `(1-a)/(1-a) = 1` for any `a`. This is the general allpass property (unity magnitude at every frequency, DC included), and `DelayDiffuser` cascades three such sections (`StereoField.hpp:185-188`), which stays unity at DC. Claim confirmed.
- **`OutputLimiter` is a pure envelope-following scalar.** `dsp::OutputLimiter::Process(float x)` (`app/dsp/Limiter.hpp:423`) is exactly `x * NextGain(std::fabs(x))` — a multiply by a slowly-varying gain, no filtering. It cannot block DC.
- **Nothing else sits between the line read and `lastWet`.** Traced `Process()` (`app/dsp/Delay.hpp:653-862`): `dL/dR` (ReadAt) → `ApplyReverse` blend (linear combination, no DC blocking) → `ApplyDiffusion` (unity at DC, above) → `wetLimiterL/R.Process` → `lastWet`. The feedback-path tone filter (`fbToneL/R`) sits only on the recirculating tap, not this wet path.
- The `rms(side)/rms(mid) = sqrt((1-rho)/(1+rho))` identity at equal levels, and the `2ab/(a²+b²)` weighting at unequal levels, both check out algebraically (derived independently from `mid=(L+R)/2`, `side=(L-R)/2`).

**No defect.**

## Repair 3 — the drift check (proposal.md item 6 / tasks.md 1.4)

**The before/after PASS/FAIL diff has a hole, and I found a concrete instance.** `randomize_all_storm_test_never_blows_out_or_permanently_silences` is a genuine pin (width and feedback both drawn, live, over 200 draws), and its RNG source (`ParameterManager::randomEngine_`, an `std::mt19937` seeded with the fixed constant `0x51EA5EEDu`, `External/Sheaf/projects/synth/include/synth/ParameterModulation.hpp:933`, no `SetRandomSource` override in this test) is deterministic — so it is not "flaky" in the non-reproducible sense. The hole is different: **its assertions cannot detect the specific regression this change exists to prevent.** It asserts only global finiteness, no over-scale, and `peak <= kSilenceEpsilon` where `peak` is the max absolute sample **across both channels combined** (`app/FroggersAudioRoutingTests.cpp:894-899`). Finding 3's disqualified failure mode is exactly "exact silence in the right channel" while the left channel stays loud — a case this test's own `peak` computation is structurally blind to (max over both channels stays high even if one channel goes to exact zero). So this test can be a "pin" by the stated criterion, run every stage gate, and report PASS before and after a regression that silences one channel — the drift check gives zero signal for the one failure class Findings 3/4 already identified as the disqualifying one. This directly falsifies proposal.md's own claim that the diff "finds a pin whatever spelling assigns its width, including the randomize-driven cases." **Blocking task 1.4** — either add a per-channel-balance assertion reachable by this path, or explicitly narrow task 1.4's claim about what the drift check does and does not catch.
